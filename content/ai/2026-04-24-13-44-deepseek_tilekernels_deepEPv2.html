PART 01

TileKernels：下一代模型的"生产级地基"

基于 TileLang 编写，无需手写 CUDA C++，实现"Python 写代码，自动生成接近硬件极限的 GPU 内核"

技术路线重大转向

全部基于 TileLang（DeepSeek 自研 Python DSL）编写，无需手写 CUDA C++。这是对英伟达 CUDA 生态的一次关键突破，解决了"GPU 算子人才稀缺、迭代慢、跨硬件难"的行业痛点。

Python DSL 自动 Kernel 生成

Engram 条件记忆模块

通过 哈希查表以 O(1) 复杂度 检索静态知识，为模型主干卸载记忆负担，与 MoE 的条件计算形成完美互补。此前仅有论文和演示代码，现公开生产级内核。

O(1) 检索 静态知识卸载

Manifold HyperConnection (mHC)

改进了字节 Seed 团队的 HyperConnection，用双随机矩阵约束解决了大规模训练时的信号发散问题，是万亿级模型稳定训练的关键保障。

覆盖全链路核心算子

  • MoE 路由与门控
  • FP8 / FP4 / E5M6 多精度量化（融合 SwiGLU）
  • 批量转置、RMSNorm 等
  • 多数已在 DeepSeek-V3/R1 内部投入生产使用
PART 02

DeepEP v2：万亿级 MoE 训练的"通信高速公路"

彻底重构专家并行框架，仅需几分之一的 SM 资源即可达到极致性能

彻底重构专家并行 (EP) 框架

解决了 V1 版本积累的历史包袱和性能问题，仅需几分之一的 SM 资源即可达到极致性能，让更多 GPU 资源能用于实际计算而非通信。

支持超大规模扩展

大幅提升了单机 (Scale-up) 和跨机 (Scale-out) 能力，为训练万亿甚至十万亿参数级别的 MoE 模型扫清了通信瓶颈。

革命性的 "0 SM" 技术

推出实验性的 0 SM Engram、0 SM 流水线并行 (PP)、0 SM 上下文并行 (CP) 的 All-gather 算子，实现了"通信不占用 GPU 计算资源"的理想状态。

后端升级：NCCL Gin + Fully JIT

从 NVSHMEM 切换为更轻量的 NCCL Gin 后端（仅头文件），同时支持全时即时编译 (Fully JIT)，部署更灵活。

PART 03

对 DeepSeek 自身的战略意义

下一代模型已进入工程落地阶段

Engram 和 mHC 此前只有论文和演示代码，现在公开生产级内核，说明 DeepSeek 已在为将这些组件集成到 DeepSeek-V4 做最后的工程准备。

训练成本将进一步大幅下降

结合之前开源的 DeepGEMM 和 FP4 Indexer，DeepSeek 已构建了完整的自主可控底层技术栈，在相同硬件条件下能实现比同行更高的训练效率。

推理速度和长文本能力质变

Engram 能显著提升模型处理静态知识的速度，而 DeepEP v2 的通信优化将让大规模 MoE 模型的推理延迟大幅降低。
